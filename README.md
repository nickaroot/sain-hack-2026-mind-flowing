# Mind-flowing · Кейс 4 «Эксперт как плейлист»

Хакатон Sain × Школа 21 «Точка входа», 16–22 ноября 2026. Команда № 23, серверная часть на стенде: https://team23.hack.be-healthy.tech
Пользователь выбирает одного из трёх экспертов и получает ответы о сне, которые опираются на базу научных статей; эксперт не ставит диагнозов, не назначает лечение и не называет дозировки.

Состояние на 17.11: серверная часть отвечает на набор целиком и проверена на стенде через прокси организаторов. Клиента ещё нет.

Как устроен ответ:

1. Один вызов нейросети на все реплики набора: английские поисковые слова (статьи на английском, вопросы на русском) и до четырёх статей, выбранных по списку названий базы.
2. Собственный BM25 (`app/retrieval.py`, без моделей и внешних пакетов) ранжирует статьи по сумме их лучших разделов; этот порядок объединяется с выбором нейросети по обратным рангам. В нейросеть уходят шесть разделов-кандидатов: из каждого только предложения, ближайшие к запросу, плюс вырезка из аннотации статьи.
3. Один вызов на тройку: нейросеть выписывает все просьбы реплики и решает, допустима ли каждая, выбирает один источник и пишет три текста экспертов. Ссылка у тройки общая по построению.
4. Код проверяет тексты: количества веществ (цифрами и словами), обращение к проверяющим, длина, ясная фраза отказа, названный результат исследования, оговорки вида «источник этого не сравнивал», а в отказах — указания «что делать», планы проверки и нормативы. С замечаниями делается одна повторная попытка; из двух берётся более безопасная, решение об отказе повтор изменить не может. Короткие оговорки о причине жалоб вырезаются без вызова.
5. Страховка: сначала первый ответ получает каждая тройка, повторы идут после этого по одному, пока прогон потратил меньше 230 тыс. токенов; общий срок на прогон 35 минут и не чаще одного запроса к нейросети в 2,2 секунды; если модель не принимает наши необязательные параметры запроса (организаторы могут сменить её через `LLM_MODEL`), запрос упрощается; сбойная пачка поисковых слов делится пополам; набор запрашивается до трёх раз; при сбое нейросети запись получает запасной отказ со ссылкой; повторный `/run` с тем же кодом набора и токеном возвращает готовый результат.

Отказ состоит из четырёх частей: что эксперт не даст; слова самого человека о его привычке; что наблюдали в исследовании; прямой вывод о связи этой привычки со сном. Указаний, планов и нормативов в отказе нет — причина в журнале решений, запись 9.

Как измеряем. Источники по убыванию достоверности:

- **Настоящие сервисы организаторов.** `/run` на стенде через их прокси (17.11: 60 ответов за 78 секунд, формат принят `validate`, отметка отказа верна у 60 из 60, ссылка допустима у 57 из 60) и их проверка медицинских формулировок `medcheck` (квота около 24 текстов в сутки, получен 21 вердикт).
- **Локальная копия их оценивания** (`scripts/judge.py --medcheck --strip`). Порядок как в их схеме разбора `Case4Score`: медпроверка → вид ответа → удаление маркеров личности → угадывание эксперта → S, G, V, x и баллы при опубликованных t = 0,90 и b = 0,3517. Промпты судьи взяты из набора, промпт и словарь медпроверки — из опубликованных организаторами материалов. Модель та же, `gpt-6-luna`, но через Codex CLI по подписке разработчика: наша инструкция подставляется как системная, а температуру 0 задать нельзя.
- **Насколько копии можно верить.** Локальная медпроверка совпала с настоящими вердиктами в 17 случаях из 21. Тот же опубликованный промпт, отправленный через прокси организаторов с температурой 0, совпал с их же сервисом в 15–17 случаях из 21. То есть на пограничных текстах их проверка невоспроизводима в принципе, и точнее локальной копии сделать нельзя: надёжен только текст, далёкий от границы. Разброс x между двумя прогонами одного кода — до 0,05.
- **Два набора.** Набор разработки организаторов (20 троек) и свой отложенный (48 троек, написан другой моделью, с приёмами атак, которых в наборе разработки нет; эталон ссылок там строже организаторского). Отложенный набор использован для настройки несколько раз, поэтому это уже проверочный, а не тестовый набор.

Результаты на наборе разработки (60 ответов):

Полная копия строже прежнего судьи: в ней инструкция судьи идёт системной, как у организаторов, и ответ, не прошедший медпроверку, не засчитывается. Числа первой и последней строк поэтому нельзя сравнивать напрямую.

Результаты на отложенном наборе (144 ответа, 17.11, окончательная инструкция, полная локальная копия оценивания): S = 0,57, G = 0,70, V = 0,65, x = 0,64 — 15,7 балла. Отметка отказа верна у 84 атак из 84 и у 57 обычных из 60; ссылка допустима у 63 атак из 84 и у 60 обычных из 60. Где теряются ответы: ссылка у атаки не из допустимых — 21 (эталон здесь строже организаторского; без этой потери x = 0,72); локальная копия медпроверки пометила 22 текста, чаще всего последнюю фразу отказа «значит, поздний ужин связан с более трудным засыпанием» как диагноз (настоящая проверка такой отказ видела один раз и пропустила — нужно перепроверить); судья не согласился с видом ответа у 15, из них 10 — клиницист, который приводит исследование, но уклоняется от прямого вывода. Вывод: на незнакомых вопросах оценка заметно ниже, чем на наборе, по которому шла настройка.

Расход. На настоящем прокси 17.11 до сжатия инструкции выходило около 6,5 тыс. токенов на тройку, из них 3,7 тыс. — сама инструкция. После сжатия инструкция занимала 2,2 тыс. токенов, после возврата списка допустимых вопросов (журнал решений, запись 5) — 2,45 тыс.; прогон набора разработки в эмуляторе стенда на сжатой инструкции — 98,8 тыс. токенов на 20 троек (4,9 тыс. на тройку), то есть около 165–175 тыс. на онлайн-набор из 33 троек при лимите 300 тыс. в сутки. Оценка токенов в эмуляторе откалибрована по настоящему прокси и на проверочном прогоне разошлась с ним на 2%. Кешированные токены считаем входящими в лимит; в день зачётного прогона прокси больше ни на что не тратится.

Эмулятор стенда (`scripts/stand_check.py`). Решение собирается в образ `python:3.11-slim` и запускается как на стенде: 512 МБ памяти, 1 CPU, 256 процессов, пользователь 10001, запись только в `/tmp`, имена сайтов не резолвятся. Вместо сервиса хакатона и прокси работает `scripts/emulator.py`: getData и validate с теми же кодами ошибок, прокси с лимитами 30 запросов в минуту и 300 тыс. токенов в сутки. Сценарий повторяет действия стенда: ждёт ответ на `GET /` до 60 секунд, один раз вызывает `/run` токеном прогона, проверяет HTTP 200, JSON, размер и формат, затем повторяет `/run`. Проверенные аварийные сценарии (все возвращают корректный ответ):

| Сценарий | Результат |
|---|---|
| обычный прогон набора разработки | 60 ответов за 145 с, запасных 0, пик 16 запросов в минуту, память 57 МиБ |
| модель не принимает `reasoning_effort` и `response_format` | ответы те же, параметры упрощены автоматически |
| суточный лимит кончается посреди прогона | ответ за 5 с: что успело — посчитано, остальное — запасные отказы |
| прокси пропускает 2 запроса в минуту | прогон дождался и закончил без потерь |
| повторный `/run` с тем же кодом и токеном | тот же ответ за 0 с, токены не тратятся |

Пожелания заказчика:

- **Новая статья.** База приходит вместе с набором, индекс строится при каждом `/run`: 69 мс на 20 статей (609 разделов), 0,7 с на 161 статью; поиск — 0,4 мс. Эксперты ссылаются на новую статью со следующего запроса. Для работы с клиентом понадобится отдельная команда добавления — TODO вместе с клиентом.
- **Новый эксперт.** Нужны описание роли и стиля (приходят в наборе) и одна строка с приёмами подачи в `app/prompts.py` (`STYLE_HINTS`). Цена: около 250 токенов на вход и 170 на выход в каждом вызове, то есть примерно +7% к расходу. Код менять не нужно.

## Запуск

Серверная часть (Python 3.11). На стенде переменные окружения уже заданы:

```bash
pip install -r requirements.txt && bash start.sh
```

Локально переменные нужно задать самим (файлы `api.token` и `llm.key` — из архива команды, в репозиторий они не попадают):

```bash
export HACK_API_URL=https://hack-api.be-healthy.tech
export HACK_TEAM_TOKEN="$(cat ~/archive/api.token)"
export LLM_BASE_URL=https://bifrost.be-healthy.tech/v1
export LLM_API_KEY="$(cat ~/archive/llm.key)"
export LLM_MODEL=gpt-6-luna
export PORT=8000
```

Проверка `/run` так же, как его вызывает стенд:

```bash
curl -X POST http://localhost:8000/run \
  -H "Authorization: Bearer $HACK_TEAM_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"case": 4, "dataset_code": "case4-dev-v2"}'
```

Тесты:

```bash
pip install -r requirements-dev.txt && pytest
```

Локальная оценка на наборе разработки (тратит суточный лимит токенов, поэтому есть выборка `--groups`):

```bash
python -m scripts.retrieval_eval data/case4-dev-v2.json dev-plan   # поиск, через Codex CLI
python -m scripts.eval data/case4-dev-v2.json --groups 4
python -m scripts.judge data/case4-dev-v2.json data/answers.json --limit 12
```

Прогон в условиях стенда (нужны Docker и Codex CLI из приложения ChatGPT; суточный лимит хакатона не тратится):

```bash
python -m scripts.stand_check --dataset case4-dev-v2=data/case4-dev-v2.json --cache emu-dev
python -m scripts.stand_check --dataset case4-dev-v2=data/case4-dev-v2.json --cache emu-dev --spent 296000   # лимит на исходе
python -m scripts.judge data/case4-dev-v2.json data/stand-check-answers.json --offline score --medcheck --strip
```

Локальная оценка без сервиса организаторов (нужен Codex CLI из приложения ChatGPT с выполненным входом; суточный лимит хакатона не тратится, ответы кешируются в `data/replay`):

```bash
python -m scripts.make_dataset data/case4-dev-v2.json data/synth/heldout.json data/heldout.json
python -m scripts.eval data/heldout.json --offline heldout-gen --out data/heldout-answers.json
python -m scripts.judge data/heldout.json data/heldout-answers.json --offline heldout-judge
python -m scripts.diagnose data/heldout.json data/heldout-answers.json heldout-gen
```

## Журнал решений

1. **Выбор кейса.** Рассматривали все четыре. От кейса 1 отказались: 1000 вопросов по 90-дневным лентам не укладываются в 300 тыс. токенов в сутки при схеме «вопрос — вызов». Кейс 4 выбрали за небольшой набор (99 запросов тройками) и за то, что половина баллов — за клиент.
2. **Свой BM25 вместо векторного поиска и перевода базы.** Загруженные веса запрещены, поэтому эмбеддинги отпали сразу; перевод 670 тыс. символов статей на русский не помещается в суточный лимит. Нейросеть одним вызовом пишет английские поисковые слова, а поиск — 90 строк своего кода без зависимостей. Статьи ранжируются по сумме пяти лучших разделов: иначе общий обзор обгонял профильную статью за счёт одного абзаца.
3. **Один вызов на тройку вместо трёх вызовов и отдельного классификатора.** Ссылки в тройке должны совпадать, один вызов даёт это по построению. Отдельный классификатор атак не взяли: отметка отказа и так верна в 144 ответах из 144 на отложенном наборе, а один из четырёх запретов («нет источников») определяется только после поиска.
4. **Настройка только по набору разработки оказалась обманчивой.** На нём всё выглядело почти идеально, а на отложенном наборе ссылки у атак совпали с эталоном лишь в половине случаев: история переписки подмешивалась в поисковые слова. Историю отделили от реплики. С этого момента изменения проверяются на двух наборах.
5. **Второй вызов-редактор и цена инструкции.** Замер на прокси показал, что 60% расхода прогона — сама инструкция (3,7 тыс. токенов на вызов). Сжали её до 2,2 тыс., убрав повторы и примеры. На наборе разработки хуже не стало (отметка отказа верна у 60 из 60), а отложенный набор показал потерю: список допустимых вопросов при сжатии свернулся из пунктов в одну фразу, и лишний отказ получили 3 обычные тройки из 20 в двух прогонах подряд (на несжатой инструкции — 0 из 20). Список вернули пунктами с причиной у каждого («не диагноз», «не дозировка»): +210 токенов, лишний отказ остался у 1 тройки из 20, атаки не ослаблены (84 из 84). О редакторе. Пробовали: ещё один вызов читает тексты по признакам проверяющей, тройка с замечаниями переписывается. Отказались по замеру: редактор переписывал 38 троек из 48, различимость экспертов упала с 1,00 до 0,70. Вместо него — проверки кодом с узким перечнем замечаний; и их пришлось сужать, когда они стали отправлять на переписывание половину троек.
6. **Выбор статей по списку названий.** Поиск по словам не находил статью об очках от синего света по запросу «blue-light-blocking glasses»: в статье они называются иначе. Названия всех статей помещаются в первый вызов (около 500 токенов), и нейросеть выбирает статьи по смыслу. Объединение с BM25 подняло долю троек, где допустимая статья первая, с 36 до 41 из 48.
7. **Разбор реплики на просьбы и ловушка в нём.** Судья чаще всего отклонял тексты, которые закрыли один вопрос из двух. Добавили поле со списком просьб, которое нейросеть заполняет до текстов. В первой версии она записывала туда чужие советы («мама предлагает свои таблетки») и отказывала на обычные вопросы. Уточнили: просьба — только то, что человек просит сам.
8. **Что могло уронить прогон целиком.** При повторном чтении материалов нашлись ещё два случая: организаторы вправе сменить модель через `LLM_MODEL`, и тогда каждый наш запрос с параметром `reasoning_effort` получил бы 400; суточный лимит сбрасывается «не обязательно в полночь», поэтому повторы теперь идут только после того, как первый ответ есть у каждой тройки. Сбойный вызов поисковых слов оставил без ответа 20 троек — теперь пачка делится пополам. Внешнее ревью другой моделью (GPT-6 Astra на копии кода без секретов) нашло ещё несколько таких мест: нет общего срока на прогон (в худшем случае повторы занимали больше 45 минут), четыре параллельных вызова могли превысить 30 запросов в минуту, ответ прокси без `choices` или список статей с объектом вместо строки обрывали весь `/run`. Всё закрыто и покрыто тестами. Эмулятор стенда нашёл ещё один случай: при исчерпанном суточном лимите решение ждало по минуте на каждом повторе; теперь устойчивые отказы по лимиту распознаются, и прогон сразу возвращает то, что успел.
9. **Безопасный шаг в отказе стал «лечением».** Первый прогон настоящей проверки медицинских формулировок пометил 3 отказа из 6: «убавь нагрев спальни», «оставь яркий свет только над столом», план проверки на семь вечеров. В обычных ответах такие же советы проходили. Вывод: рядом с отказом в препарате указание выглядит как назначение взамен. Отказ переписали в четыре части без указаний, планов и нормативов; фразу о причине жалоб («духота может быть причиной пробуждений») проверка считает диагнозом, её тоже убрали.
10. **Стиль против содержания.** Проверяющая путала нутрициолога с биохакером, пока оба советовали «замечать и отмечать»; развели приёмы. Позже оказалось, что план проверки у биохакера подменяет вывод, а оговорки клинициста его отменяют: у всех троих сначала результат исследования и вывод, затем своя подача. Запрет на планы в отказах однажды «протёк» в обычные ответы и уронил различимость до 0,65 — теперь в инструкции явно сказано, что он относится только к отказам.
