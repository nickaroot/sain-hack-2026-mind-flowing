# Mind-flowing · Кейс 4 «Эксперт как плейлист»

Хакатон Sain × Школа 21 «Точка входа», 16–22 ноября 2026. Команда № 23, серверная часть на стенде: https://team23.hack.be-healthy.tech
Пользователь выбирает одного из трёх экспертов и получает ответы о сне, которые опираются на базу научных статей; эксперт не ставит диагнозов, не назначает лечение и не называет дозировки.

Состояние на 16.11: серверная часть отвечает на набор целиком. Клиента ещё нет.

Как устроен ответ:

1. Один вызов нейросети на все реплики набора: английские поисковые слова (статьи на английском, вопросы на русском) и до четырёх статей, выбранных по списку названий базы.
2. Собственный BM25 (`app/retrieval.py`, без моделей и внешних пакетов) ранжирует статьи по сумме их лучших разделов; этот порядок объединяется с выбором нейросети по обратным рангам. В нейросеть уходят шесть разделов-кандидатов: из каждого только предложения, ближайшие к запросу, плюс вырезка из аннотации статьи.
3. Один вызов на тройку: нейросеть выписывает все просьбы реплики и решает, допустима ли каждая, выбирает один источник и пишет три текста экспертов. Ссылка у тройки общая по построению.
4. Код проверяет тексты: количества веществ, обращение к проверяющим, длина, ясная фраза отказа, названный результат исследования, оговорки вида «источник этого не сравнивал». С замечаниями делается одна повторная попытка; из двух берётся та, где замечаний меньше.
5. Страховка: при сбое нейросети запись получает запасной отказ со ссылкой; сбойная пачка поисковых слов делится пополам и запрашивается заново; после 230 тыс. токенов за прогон повторов нет; повторный `/run` с тем же кодом набора возвращает готовый результат.

Как измеряем. Отвечает и судит та же модель `gpt-6-luna`, но через Codex CLI и подписку разработчика, чтобы не тратить суточный лимит хакатона; судья работает по промптам проверяющей, опубликованным в наборе. Числа близки к настоящей проверке, но не совпадают с ней: Codex добавляет свою инструкцию агента. Наборов два: набор разработки организаторов `case4-dev-v2` (20 троек) и свой отложенный (48 троек: 20 обычных вопросов и 28 атак, написаны другой моделью, с приёмами, которых в наборе разработки нет; эталон ссылок там строже организаторского, поэтому S на нём занижена).

Поиск: допустимая статья стоит первой у 41 тройки из 48 против 36 при поиске только по словам; на базе, увеличенной до 153 статей, — у 38 против 30.

## Запуск

Серверная часть (Python 3.11). На стенде переменные окружения уже заданы:

```bash
pip install -r requirements.txt && bash start.sh
```

Локально переменные нужно задать самим (файлы `api.token` и `llm.key` — из архива команды, в репозиторий они не попадают):

```bash
export HACK_API_URL=https://hack-api.be-healthy.tech
export HACK_TEAM_TOKEN="$(cat ~/archive/api.token)"
export LLM_BASE_URL=https://bifrost.be-healthy.tech/v1
export LLM_API_KEY="$(cat ~/archive/llm.key)"
export LLM_MODEL=gpt-6-luna
export PORT=8000
```

Проверка `/run` так же, как его вызывает стенд:

```bash
curl -X POST http://localhost:8000/run \
  -H "Authorization: Bearer $HACK_TEAM_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"case": 4, "dataset_code": "case4-dev-v2"}'
```

Тесты:

```bash
pip install -r requirements-dev.txt && pytest
```

Локальная оценка на наборе разработки (тратит суточный лимит токенов, поэтому есть выборка `--groups`):

```bash
python -m scripts.retrieval_eval data/case4-dev-v2.json dev-plan   # поиск, через Codex CLI
python -m scripts.eval data/case4-dev-v2.json --groups 4
python -m scripts.judge data/case4-dev-v2.json data/answers.json --limit 12
```

Локальная оценка без сервиса организаторов (нужен Codex CLI из приложения ChatGPT с выполненным входом; суточный лимит хакатона не тратится, ответы кешируются в `data/replay`):

```bash
python -m scripts.make_dataset data/case4-dev-v2.json data/synth/heldout.json data/heldout.json
python -m scripts.eval data/heldout.json --offline heldout-gen --out data/heldout-answers.json
python -m scripts.judge data/heldout.json data/heldout-answers.json --offline heldout-judge
python -m scripts.diagnose data/heldout.json data/heldout-answers.json heldout-gen
```

## Журнал решений

1. **Выбор кейса.** Рассматривали все четыре. От кейса 1 отказались: 1000 вопросов по 90-дневным лентам не укладываются в 300 тыс. токенов в сутки при схеме «вопрос — вызов». Кейс 4 выбрали за небольшой набор (99 запросов тройками) и за то, что половина баллов — за клиент.
2. **Свой BM25 вместо векторного поиска и перевода базы.** Загруженные веса запрещены, поэтому эмбеддинги отпали сразу; перевод 670 тыс. символов статей на русский не помещается в суточный лимит. Вместо этого нейросеть одним вызовом пишет английские поисковые слова, а поиск — 90 строк своего кода без зависимостей. Статьи ранжируются по сумме пяти лучших разделов: иначе общий обзор обгонял профильную статью за счёт одного абзаца.
3. **Один вызов на тройку вместо трёх вызовов и отдельного классификатора.** Ссылки в тройке должны совпадать, один вызов даёт это по построению. Отдельный классификатор атак не взяли дважды: в начале из-за цены и позже по замеру — отметка отказа и так верна в 144 ответах из 144, а один из четырёх запретов («нет источников») определяется только после поиска.
4. **Настройка только по набору разработки оказалась обманчивой.** На нём всё выглядело почти идеально, а на отложенном наборе ссылки у атак совпали с эталоном лишь в половине случаев: история переписки подмешивалась в поисковые слова. Историю отделили от реплики. С этого момента каждое изменение проверяется на двух наборах.
5. **Жёсткий фильтр количеств.** Ответы про кофеин с миллиграммами фильтр молча заменял запасным отказом, и обычный вопрос получал отметку отказа. Теперь замечание возвращается нейросети одной повторной попыткой.
6. **Второй вызов-редактор.** Пробовали: ещё один вызов читает тексты по признакам проверяющей, тройка с замечаниями переписывается. Отказались по замеру: редактор переписывал 38 троек из 48, различимость экспертов упала с 1,00 до 0,70, польза не выросла. Вместо него — проверки кодом с узким перечнем замечаний.
7. **Выбор статей по списку названий.** Поиск по словам не находил статью об очках от синего света по запросу «blue-light-blocking glasses»: в статье они называются иначе. Названия всех статей помещаются в тот же первый вызов (около 500 токенов), и нейросеть выбирает статьи по смыслу. Объединение с BM25 подняло долю троек, где допустимая статья первая, с 36 до 41 из 48.
8. **Разбор реплики на просьбы и ловушка в нём.** Судья чаще всего отклонял тексты, которые закрыли один вопрос из двух. Добавили поле со списком просьб, которое нейросеть заполняет до текстов. В первой версии она записывала туда чужие советы («мама предлагает свои таблетки») и отказывала на обычные вопросы — три тройки из 40. Уточнили: просьба — только то, что человек просит сам.
9. **Один сбойный вызов стоил 20 троек.** Вызов, который готовит поисковые слова пачкой по 20 реплик, один раз не ответил, и все 20 получили запасной отказ. Теперь пачка при сбое делится пополам и запрашивается заново.
10. **Стиль против содержания.** Проверяющая путала нутрициолога с биохакером, пока оба советовали «замечать и отмечать»; развели приёмы. Позже оказалось, что план проверки у биохакера подменяет вывод, а оговорки клинициста его отменяют: теперь у всех троих сначала результат исследования и вывод, затем своя подача.
