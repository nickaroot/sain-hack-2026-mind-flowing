# Клиент

Здесь будет клиентская часть кейса 4: экран выбора эксперта и экран разговора с экспертом.

На финале клиент разворачивают на компьютере организаторов, и он обращается к серверной части на стенде. Поэтому адрес сервера задаётся настройкой (например, `VITE_API_URL`), а запуск — одна команда. Команду запуска нужно вписать в корневой README, раздел «Запуск».

## Методы серверной части

Адрес на стенде: `https://team23.hack.be-healthy.tech`. Запросы из браузера с любого адреса разрешены (CORS), ключей и авторизации нет. Все ответы — JSON.

### `GET /api/experts` — кого показать на экране выбора

```json
{
  "experts": [
    {
      "expert_id": "clinician",
      "name": "Сомнолог-клиницист",
      "description": "Думает как врач, который читает исследования: сначала механизм, затем сила доказательств…",
      "speech_style": "Спокойные полные предложения, ровный темп, без восклицаний, сленга и шуток…"
    },
    {"expert_id": "biohacker", "name": "Биохакер-экспериментатор", "description": "…", "speech_style": "…"},
    {"expert_id": "nutritionist", "name": "Нутрициолог здравого смысла", "description": "…", "speech_style": "…"}
  ],
  "user_id": null
}
```

Список приходит из набора организаторов: новый эксперт появится здесь без изменений в клиенте. `description` и `speech_style` — длинные тексты для нейросети; для карточки эксперта лучше написать свои короткие подписи, а эти показать по нажатию «подробнее». `user_id` — пользователь, от чьего имени идёт разговор. На финале в наборе один пользователь, и сервер подставит его сам. В наборе разработки пользователей два, поэтому здесь `null`; чтобы сервер учёл прежнюю переписку одного из них, передайте в `POST /api/chat` поле `user_id` (`u_t7r4q9` или `u_m4r7z1`).

### `POST /api/chat` — задать вопрос

Запрос:

```json
{
  "expert_id": "biohacker",
  "text": "Мешает ли чашка кофе после обеда уснуть вечером?",
  "history": [
    {"role": "user", "text": "Я ложусь в одиннадцать."},
    {"role": "assistant", "text": "Понял, отбой в одиннадцать."}
  ]
}
```

`history` — предыдущие реплики этого разговора в клиенте, от старых к новым, не больше 20; можно не передавать. `text` и каждая реплика — до 2000 символов, всё тело запроса — до 64 КБ. Прежнюю переписку пользователя из набора сервер добавляет сам. Нейросеть видит только последние 8 реплик (переписка из набора плюс текущий разговор), каждую до 500 символов: если уточнение опирается на что-то сказанное давно, это стоит повторить в вопросе.

Ответ:

```json
{
  "expert_id": "biohacker",
  "text": "Да, кофе после обеда может сдвинуть засыпание. В рандомизированном перекрёстном исследовании…",
  "refused": false,
  "degraded": false,
  "answers": {
    "clinician": {"text": "Да, чашка кофе после обеда может затруднить засыпание вечером…", "refused": false},
    "biohacker": {"text": "Да, кофе после обеда может сдвинуть засыпание…", "refused": false},
    "nutritionist": {"text": "Да, чашка кофе после обеда может мешать заснуть вечером…", "refused": false}
  },
  "citations": [
    {
      "article_id": "art_20", "section_id": "s001",
      "article_title": "Dose and timing effects of caffeine on subsequent sleep: a randomized clinical crossover trial",
      "section_title": "Abstract › Study Objectives", "year": 2025, "doi": "10.1093/sleep/zsae230"
    }
  ]
}
```

- `text` и `refused` — ответ выбранного эксперта. `answers` — тот же ответ голосами всех трёх, у каждого свой `refused`: переключение эксперта можно показать сразу, без нового запроса. Повторный запрос того же вопроса с другим `expert_id` тоже отвечает мгновенно и не тратит лимит нейросети.
- `refused: true` — эксперт отказал (просили диагноз, лечение, дозировку или совет, о котором в базе нет исследований). Это обычный ответ эксперта со ссылкой, статус 200. Показывать его нужно как реплику эксперта, а не как ошибку: так требует условие кейса. Обычно флаг одинаков у всех троих; при переключении эксперта берите флаг из `answers`.
- `citations` — одна ссылка: статья и раздел, на которые опирается ответ. Статьи на английском.
- `degraded: true` — нейросеть не ответила, выбранному эксперту ушёл короткий запасной текст. Стоит предложить повторить вопрос.

Время ответа — обычно 10–20 секунд (замер на стенде: 10,5 с). Сервер отвечает не позже чем через 90 секунд: нужен индикатор «эксперт печатает» и ожидание в клиенте не меньше 100 секунд. Тот же вопрос, отправленный повторно (двойное нажатие, повтор после 504), второй раз не считается: сервер ждёт уже начатый расчёт или отдаёт готовый ответ.

Ошибки (тело `{"detail": "текст для человека"}`):

| Статус | Когда | Что показать |
|---|---|---|
| 422 | пустой или слишком длинный текст | проверить ввод до отправки |
| 413 | тело запроса больше 64 КБ | не должно случаться при соблюдении ограничений |
| 404 | неизвестный `expert_id` | не должно случаться, если список взят из `/api/experts` |
| 429 | одновременно считается слишком много вопросов (`Retry-After: 15`) или исчерпан дневной запас разговоров (`Retry-After: 3600`) | «эксперты заняты, повторите через несколько секунд» или «на сегодня вопросы закончились» — по тексту `detail` |
| 503 | сервер занят обработкой набора, база ещё не загружена или действует пауза перед зачётным прогоном | «попробуйте через минуту», заголовок `Retry-After` |
| 504 | ответ не успел за 90 секунд | предложить повторить тот же вопрос: расчёт продолжается, повтор его дождётся |

### `GET /api/sources/{article_id}/{section_id}` — показать источник

```json
{
  "article_id": "art_20", "section_id": "s001",
  "article_title": "Dose and timing effects of caffeine on subsequent sleep: a randomized clinical crossover trial",
  "section_title": "Abstract › Study Objectives", "year": 2025, "doi": "10.1093/sleep/zsae230",
  "text": "To investigate the effect of a typical dose of caffeine and a high dose of caffeine…"
}
```

Текст раздела для экрана или всплывающего окна «источник». Ссылку на статью можно собрать как `https://doi.org/<doi>`.

## Голос

Ключ прокси есть только у сервера, поэтому браузер за голосом ходит к нему же. Оба метода проверены на настоящем прокси 19.11: синтез фразы в 120 символов — 3–8 секунд и около 130 КБ mp3, распознавание — около 3 секунд.

### `POST /api/transcribe` — запись вопроса → текст

Тело запроса — сами байты записи, тип — в заголовке `Content-Type`. Никакого `multipart` не нужно:

```js
const recorder = new MediaRecorder(stream)            // даёт audio/webm;codecs=opus
// … собрать куски в blob …
const response = await fetch(`${API_URL}/api/transcribe`, {
  method: "POST", headers: { "Content-Type": blob.type }, body: blob,
})
const { text } = await response.json()                // дальше text уходит в POST /api/chat
```

Принимаются `audio/webm`, `audio/ogg`, `audio/mpeg`, `audio/wav`, `audio/mp4` (m4a), `audio/flac`; запись — до 5 МБ, это больше десяти минут webm из браузера. Ответ: `{"text": "Мешает ли чашка кофе после обеда уснуть вечером?"}`.

### `POST /api/speak` — ответ эксперта → mp3

```json
{"text": "Да, чашка кофе после обеда может мешать уснуть…", "expert_id": "biohacker"}
```

Ответ — `audio/mpeg`, его можно сразу проиграть:

```js
const audio = new Audio(URL.createObjectURL(await response.blob()))
audio.play()                                          // запускать по нажатию: автозапуск звука браузер запретит
```

У каждого эксперта свой голос (клиницист, биохакер и нутрициолог звучат по-разному), у неизвестного `expert_id` — голос по умолчанию. Текст — до 2000 символов. Повторное прослушивание того же текста тем же экспертом сервер отдаёт из памяти мгновенно и бесплатно, а два одинаковых запроса, пришедшие одновременно (двойное нажатие), озвучиваются один раз.

Ошибки обоих методов (тело `{"detail": "текст для человека"}`):

| Статус | Когда | Что показать |
|---|---|---|
| 415 | тип записи не аудио | не должно случаться, если тип взят из `blob.type` |
| 413 | запись больше 5 МБ | «запись слишком длинная» |
| 422 | пустая запись или пустой текст | проверить до отправки |
| 429 | слишком много запросов (`Retry-After: 10` или `60`) или голос на сегодня закончился (`Retry-After: 3600`) | по тексту `detail`; при исчерпанном голосе оставить ввод и чтение текстом |
| 502 | сервис голоса недоступен | предложить повторить; интерфейс должен работать и без голоса |
| 503 | сервер занят обработкой набора | «попробуйте через минуту» |

У голоса свой суточный бюджет у организаторов (сброс в 00:00 по Москве), лимит токенов нейросети он не тратит. Но каждый его запрос входит в общие 30 запросов в минуту, так что озвучивать стоит ответ выбранного эксперта по нажатию, а не все три сразу.

## Как разрабатывать и не тратить лимит

У команды 300 тыс. токенов нейросети в сутки на всё, и зачётный прогон 20.11 берёт из того же лимита. Один вопрос в разговоре стоит около 5,6 тыс. токенов.

- Экраны собирайте на заглушках: примеры ответов выше — настоящие, их можно положить в файл и отдавать вместо сервера.
- `GET /api/experts` и `GET /api/sources/…` нейросеть не вызывают, их можно дёргать сколько угодно.
- До зачётного прогона сервер сам ограничивает разговоры 40 тыс. токенов в сутки (пять новых вопросов; повторы и переключение эксперта не считаются).
- 20.11 с 00:00 до зачётного прогона новые вопросы на стенде не принимаются вообще (ответ 503): лимит нейросети должен остаться целым. Готовые ответы из кеша отдаются. Экраны в это время проверяются на заглушках.
- Локально серверная часть запускается как описано в корневом README; с ключами из архива команды она тратит тот же общий лимит.
